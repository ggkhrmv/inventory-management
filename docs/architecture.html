Architecture overview

Factory Inventory Management System

A two-tier demo app. A Vue 3 single-page app on port 3000 calls a FastAPI service on port 8001. The service loads seven JSON files into memory at startup and filters them for each request. There is no database, and nothing the app writes is saved.

System architecture

Three layers: the browser app, the API process, and flat JSON files that the API reads once at startup.

Dark boxes are where the two tiers connect. Every view calls api.js, and every request lands on an endpoint in server/main.py. Exception: Reports.vue calls axios directly. Locale is the only state kept between sessions (localStorage["app-locale"]).

Data flow: changing a filter

What happens when someone changes the Warehouse dropdown on the Dashboard. The same sequence applies to the other filters.

  1. The FilterBar writes to shared state
    Each <select> is bound with v-model to a ref defined at module level in useFilters. Every view that calls useFilters() gets the same four refs: period, location, category, status.
    client/src/components/FilterBar.vue · client/src/composables/useFilters.js
  2. Views watch the filters they use
    Dashboard and Orders watch all four. Inventory, Demand, and Backlog watch warehouse and category. Spending watches only period, and applies it in the browser.
    client/src/views/*.vue (each view's watch([...]) call)
  3. api.js builds the request
    getCurrentFilters() maps the UI state to {warehouse, category, status, month}. api.js leaves out any value set to "all" and sends a GET with the rest as query parameters, e.g. /api/orders?warehouse=Tokyo.
    client/src/api.js
  4. FastAPI filters the in-memory lists
    apply_filters matches warehouse exactly and category and status case-insensitively. filter_by_month does a substring match on order_date and expands quarters such as Q2-2025 through QUARTER_MAP. Dashboard summary KPIs are computed here.
    server/main.py
  5. Pydantic validates, JSON goes back
    Typed routes check each record against a model (InventoryItem, Order, and so on) before serialising. If a JSON file's structure changes, the model has to be updated to match.
    server/main.py (model classes)
  6. The view recomputes and renders
    The response replaces the view's raw ref. Computed properties then update the KPI cards, tables, and SVG charts. useI18n translates labels and product names and formats currency.
    client/src/views/Dashboard.vue · client/src/composables/useI18n.js · client/src/utils/currency.js

Frontend modules

The app has no Vuex or Pinia. Shared state lives in composables: each one keeps its refs at module level, so every caller shares a single copy.

Views and their data

  • Dashboard /: summary, orders, inventory, and backlog, fetched in parallel
  • Inventory /inventory: inventory list and detail modal
  • Orders /orders: orders with all four filters
  • Demand /demand: forecasts combined with inventory
  • Spending /spending: four spending feeds and orders; period filter applied in the browser
  • Reports /reports: quarterly and monthly trends
  • Backlog: Backlog.vue exists but has no route

Composables and utilities

  • useFilters: the four filter refs, getCurrentFilters(), resetFilters()
  • useI18n: t() with English fallback, plus locale, currency, and translations for product, warehouse, and customer names
  • useAuth: a hard-coded mock user and starter tasks. There is no real authentication.
  • utils/currency: USD/JPY formatting at a fixed rate

Shell (App.vue)

Top navigation, FilterBar, LanguageSwitcher, ProfileMenu, and TasksModal. Global styles live here too.

Things worth knowing

Each of these comes from reading the code, and each one affects what happens when you add a feature.

Gap  Tasks API missing

App.vue calls GET /api/tasks on every page load and gets a 404. The error is caught and logged. Tasks created in the UI exist only in memory, and the add, toggle, and delete calls to the server fail.

Gap  Purchase-order API missing

api.js defines create and lookup calls for /api/purchase-orders, but the server has no such routes. The backlog's has_purchase_order flag reads purchase_orders.json, which is empty.

Note  Backlog view not routed

views/Backlog.vue is a complete page, but main.js registers no route for it. The Dashboard shows backlog data through BacklogDetailModal.

Note  Hard-coded API URL

http://localhost:8001/api is hard-coded in api.js, and again in Reports.vue, which skips api.js. No environment variable or Vite proxy is used.

Note  Filter support varies by endpoint

Inventory has no time dimension, so it ignores month. Demand, backlog, spending, and reports ignore all server-side filters. Month filtering is a substring match on the date string.

Note  Data generator out of date

generate_data.py still uses an old product catalogue (Widgets, Components, Equipment). The JSON data uses Circuit Boards, Sensors, Actuators, Controllers, and Power Supplies. Running it would overwrite orders.json with categories that no longer match the inventory.
